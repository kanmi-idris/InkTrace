README positioning captured from the public page:

- RuView is described as a WiFi sensing platform that turns radio-signal disturbances into spatial intelligence.
- The repo claims sensing for:
  - presence and occupancy
  - breathing rate and heart rate
  - activity recognition such as walking, sitting, gestures, and falls
  - environment mapping and room fingerprinting
  - sleep-quality monitoring and apnea screening
- The README says the system uses Channel State Information (CSI) from low-cost ESP32 sensors.
- The public page frames the system as edge-first, camera-free, and able to run without cloud or internet.

Architecture and implementation notes captured from the public README:

- The README says RuView is built on `RuVector` and `Cognitum Seed`.
- It describes an ESP32 mesh as the sensing layer, with Cognitum Seed positioned as a memory, attestation, and AI layer.
- The README says the system can use multi-frequency mesh scanning across six WiFi channels.
- The page claims pose estimation support through a WiFlow-based architecture using 17 COCO keypoints.

Important limitation notes captured from the same README:

- The repo explicitly says it is beta software and APIs and firmware may change.
- It says ESP32-C3 and the original ESP32 are not supported.
- It says single-ESP32 deployments have limited spatial resolution and recommends 2 or more nodes or an added Cognitum Seed.
- The README also explicitly states that current camera-free pose accuracy is limited, giving `PCK@20 ≈ 2.5%` with proxy labels.
- The same section says camera-ground-truth training targets `35%+ PCK@20`, but also says the data-collection and evaluation phases are still pending and that no measured camera-supervised PCK@20 has yet been published.

Interpretive note:

- This source is useful less as settled evidence that commodity home WiFi already delivers production-grade “see through walls” perception, and more as a concrete example of the current open-source WiFi-sensing stack: CSI capture, ESP32-based edge sensing, local inference, and ambitious capability claims presented alongside unusually explicit README caveats about maturity and measured pose accuracy.
