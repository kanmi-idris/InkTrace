Core architecture captured from the supplied page:

- The runner uses a two-phase model for interactions:
  - `JSI discovery`
  - `idb HID actuation`
- JSI discovery is described as a host function that walks the Fabric shadow tree, finds an element by `testID`, performs scroll/visibility/hit-test checks, and returns window coordinates.
- Actuation is then delivered as a real `UITouch` through `idb_companion` and CoreSimulator’s IOHID path.
- The README explicitly contrasts this with direct `onPress` invocation and with XCTest-style helper approaches.

Transport and runtime notes captured from the supplied page:

- The CLI drives the in-app runtime through Metro’s Hermes Inspector using CDP.
- `globalThis.__ennioDispatch` is installed as a JSI host function.
- The README says dispatch is non-blocking: work is queued and later resolved through a result slot rather than blocking the JS thread.
- The HID side is handled by a persistent Python daemon that keeps one gRPC channel warm to `idb_companion`.
