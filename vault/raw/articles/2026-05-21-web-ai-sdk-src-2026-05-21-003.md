Project framing captured from the public site:

- `web-ai-sdk` is described as:
  - “Building blocks for the Web's built-in AI APIs.”
  - “Composable. No runtime deps. Just lifecycle, streaming, and AbortSignals.”
  - “Vanilla TypeScript by default, with optional React hooks.”
- The site emphasizes:
  - 100% on-device execution
  - TypeScript-native design
  - `AsyncIterable` streaming
  - MIT licensing
  - zero dependencies

Package surface captured from the public site:

- `@web-ai-sdk/prompt`
  - wrapper for on-device language-model prompting
  - sessions
  - streaming
  - abort handling
- `@web-ai-sdk/webmcp`
  - tool registration layer over browser model context
  - declarative tool registration
  - cleanup on unmount
- `@web-ai-sdk/summarizer`
  - key-points, TL;DR, teaser, and headline summaries
  - short, medium, and long modes
  - deterministic summaries with a stable seed
- `@web-ai-sdk/translator`
  - pair-based translation
  - DOM-aware block replacement that preserves markup
  - session caching by source-target pair
- `@web-ai-sdk/detector`
  - on-device language detection
  - BCP-47 codes
  - confidence scores and alternate guesses

Architecture and philosophy captured from the public site:

- The core claim is that the library handles:
  - feature detection
  - model-download lifecycle
  - abortable streams
  - session lifetimes
  - DOM-rebuild safety
- The site frames this as a composable lifecycle layer rather than a full UI framework.
- The architecture diagram explicitly separates:
  - browser built-in AI APIs
  - `@web-ai-sdk/*` wrappers
  - optional `/react` adapters
  - user application UI

API and usage patterns captured from the public site:

- The library exposes vanilla TypeScript entry points such as:
  - `detect()`
  - `summarize()`
  - `ask()`
  - `translate()`
  - `registerTools()`
  - `defineTool()`
- It also exposes React hooks such as:
  - `usePrompt()`
  - `useSession()`
  - `useSummarizer()`
  - `useTranslator()`
  - `useDetector()`
  - `useWebMCP()`
- The site’s example argues that wrapper use can significantly shrink code compared with raw browser API usage.

Browser-support and caveat details captured from the public site:

- Support varies by package and by browser engine.
- Chrome, Edge Canary or Dev, and flag-gated or origin-trial behavior are explicitly documented.
- Safari and Firefox are described as no-op fallback environments for these wrappers at the moment.
- The site is explicit that wrappers remain stable even when underlying platform APIs are absent, with feature-detected no-op fallbacks instead of crashes.

Its durable value is not only the package list, but the clear position it takes: browser built-in AI APIs need a thin but careful lifecycle layer for sessions, streaming, model availability, and React integration, without collapsing into a heavyweight framework.
