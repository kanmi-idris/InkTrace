Core framing captured from the README:

- ShadowCat is a fully offline, single-file HTML page for moving data between two devices via QR codes.
- The intended use case is old phones whose radios such as BLE or NFC are dead, but whose cameras and browsers still work.
- The tool supports text generation and scanning through single QR codes.
- It also supports file transfer by chunking a file into QR frames and cycling through those frames at a chosen FPS.
- File sending options include chunk size, FPS, ECC level, and optional gzip compression.
- Compression automatically falls back when the gzipped payload is not smaller, such as with PDF, JPG, or MP4 files.
- Receiving uses the camera, autodetects the header, tracks chunk progress, shows missing chunks, verifies CRC, and then exposes a download button.

Protocol captured:

- Header frame:
  - `QRX1|H|<total>|<flags>|<filename>|<sizeBytes>|<crc32hex>`
- Data frame:
  - `QRX1|D|<idx>|<base64chunk>`
- Data chunks are 1-indexed.
- `<flags>` is comma-separated and empty by default.
- Defined flag:
  - `gz` means the payload is gzipped.
- `<sizeBytes>` is the on-wire size, gzipped when `gz` is set.
- `<crc32hex>` is always calculated over the original bytes.
- Base64 has no `|`, so parsing can use `split('|')`.
- The receiver tracks chunks by index, ignores duplicates, deduplicates headers by CRC, and refuses unknown flags.

Operational controls captured:

- The sender cycles through `[header, chunk1...chunkN]` forever at the chosen FPS.
- Pause, resume, and stop controls are available.
- `Start from` can begin the loop at a chosen frame index and then continue forward, wrapping back to the header.
- `Show frame` plus `Show`, `-`, and `+` can display exactly one static frame, useful for resending a missing chunk.
- The frame number matches the receiver missing-chunks grid, with `0 = header`.

Practical constraints captured:

- Camera access needs HTTPS or localhost because `file://` will not grant `getUserMedia`.
- A simple local server can be used with `python3 -m http.server 8000`, then visiting the laptop IP over the local network.
- iOS Safari additionally requires HTTPS for cross-device access, so LAN use may need Caddy or a self-signed certificate.
- If QR rendering fails with code-length overflow, lower chunk size or lower ECC level.
- The README gives an approximate throughput: `500 chars x 3 fps` is about `1.1 KB/s` base64 or `0.83 KB/s` raw, so a 100 KB file is roughly two minutes per loop.
- If old devices struggle to decode, the README recommends lowering FPS, raising ECC to Q, and shrinking chunk size to around 300 characters.

Interpretive note:

- ShadowCat is best captured as resilient, low-infrastructure data-transfer tooling for degraded devices and offline contexts.
- It is not a high-throughput transport; the README explicitly frames throughput and QR density as practical constraints.
