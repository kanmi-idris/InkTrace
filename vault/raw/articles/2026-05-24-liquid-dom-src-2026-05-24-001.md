Package architecture captured from the public README:

- `@liquid-dom/core`
  - imperative DOM-backed scene graph
  - WebGPU renderer
  - reusable glass core
  - layout classes
- `@liquid-dom/react`
  - React 19 bindings for layout and glass APIs
- `@liquid-dom/three`
  - adapter for compositing liquid glass over Three’s WebGPU renderer
- `@liquid-dom/r3f`
  - React Three Fiber bridge built on the React and Three packages
- `@liquid-dom/layout`
  - renderer-agnostic layout engine

Relationship model captured from the README:

- `@liquid-dom/layout` is described as independent.
- `@liquid-dom/core` uses it for layout but also exposes lower-level imperative scene-graph and WebGPU behavior.
- `@liquid-dom/react` wraps layout classes in React components.
- `@liquid-dom/three` hosts the reusable WebGPU core inside Three’s WebGPU renderer.
- `@liquid-dom/r3f` combines the React and Three packages for React Three Fiber.

Browser and runtime requirements captured from the README:

- The renderer requires WebGPU.
- DOM-backed HTML content additionally requires the experimental HTML-in-Canvas API.
- The README says this is currently available only behind Chrome’s `Canvas Draw Element` flag.
- It explicitly references:
  - `chrome://flags/#canvas-draw-element`
  - `canvas layoutsubtree`
  - canvas paint events
- Three integrations require Three’s WebGPU renderer, not `WebGLRenderer`.
