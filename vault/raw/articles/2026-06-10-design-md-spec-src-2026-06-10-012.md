Document framing captured:

- Title: DESIGN.md Format
- The document describes `DESIGN.md` as a self-contained, plain-text representation of a design system.
- It defines the format as a living source of truth that both humans and AI can understand and refine across design sessions, agents, and tools.

Core structure captured from the spec:

- A `DESIGN.md` file contains two parts:
  - optional YAML frontmatter for machine-readable design tokens
  - markdown body sections for human-readable rationale and guidance
- The spec explicitly says tokens are normative values, while prose provides context for how to apply them.

Token model captured from the spec:

- The token system is inspired by the Design Token JSON spec.
- It supports typed token groups such as colors, typography, spacing, rounded values, and component tokens.
- It supports token references using `{path.to.token}` syntax.
- The spec says these tokens can be converted to or from `tokens.json`, Figma variables, and Tailwind theme configs.

Schema details captured from the spec:

- Frontmatter may include `version`, `name`, `description`, `colors`, `typography`, `rounded`, `spacing`, and `components`.
- Colors accept CSS color values, including hex, named colors, `rgb()`, `hsl()`, `oklch()`, and related formats.
- Typography tokens can specify `fontFamily`, `fontSize`, `fontWeight`, `lineHeight`, `letterSpacing`, `fontFeature`, and `fontVariation`.
- Dimensions are unit-bearing values such as `px`, `em`, or `rem`.
- Token references use curly-brace paths and may reference primitive or, in component sections, composite values.

Document-section model captured from the spec:

- The spec prescribes a common section order for the markdown body:
  - Overview
  - Colors
  - Typography
  - Layout
  - Elevation & Depth
  - Shapes
  - Components
  - Do's and Don'ts
- Sections may be omitted if irrelevant, but present sections should follow the listed order.
- The prose is meant to capture brand personality, emotional intent, usage rationale, and application guidance beyond raw tokens.

Interpretive note:

- This source is strongest as a format and interoperability specification for agent-readable design-system documents.
- The durable idea is that design guidance should combine machine-readable tokens with human-readable stylistic rationale, rather than treating one as a substitute for the other.
