Key points from the supplied text:

- Android builds on EAS are described as roughly 50% faster when Gradle caching is enabled.
- Gradle caching stores task outputs and reuses them between builds.
- The changelog says this is especially helpful for projects with many native modules because repeated module tasks can be served from cache.
- Build logs can be used to verify caching, with cached tasks marked `FROM CACHE` in the Run Gradle step.
- The feature is enabled by setting `EAS_GRADLE_CACHE=1`.
- The supplied example shows this being configured under `build.production.env` in `eas.json`.
- The first build seeds the cache; later builds restore from it.
- Cache keys are described as being generated from the hash of the package manager lock file, so dependency changes naturally rotate the cache.
- The post frames Gradle cache as a complement to Expo’s earlier compiler cache support based on `ccache` for C/C++ recompilation.
- Expo says it plans to keep improving cache hit rates and extend the improvements further.
