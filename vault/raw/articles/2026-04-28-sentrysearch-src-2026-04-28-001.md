Repository description:
Semantic search over video footage. Type what you're looking for, get a trimmed clip back.

README highlights from the supplied text:

- New capability: search by image.
- SentrySearch splits videos into overlapping chunks, embeds each chunk as video using either Google's Gemini Embedding API or a local Qwen3-VL model, stores vectors in a local ChromaDB database, and returns a trimmed clip for the best match.
- Main workflow:
  - `sentrysearch init`
  - `sentrysearch index /path/to/footage`
  - `sentrysearch search "red truck running a stop sign"`
- `ffmpeg` is required for chunking and trimming, with bundled `imageio-ffmpeg` used automatically if system ffmpeg is unavailable on the Gemini path.
- Search supports confidence thresholds, top-N result saving, no-trim mode, and image-query mode via `sentrysearch img`.
- The local backend uses Qwen3-VL-Embedding models and is positioned as private and free, with auto-detection between 8B and 2B variants based on hardware.
- The README describes model- and backend-specific isolated indexes so embeddings from different models cannot accidentally mix.
- The project includes a Tesla metadata overlay mode that can burn speed, location, and time onto trimmed clips, using embedded Tesla dashcam metadata and optional reverse geocoding.
- Cost guidance is provided for the Gemini backend, with an estimate of about $2.84 per hour of indexed footage under default settings.
- Known optimizations listed:
  - downscaling chunks before embedding
  - low frame sampling
  - MRL dimension truncation
  - auto-quantization on NVIDIA
  - still-frame skipping
- Limitations called out include heuristic still-frame detection, chunk-boundary sensitivity, and Gemini Embedding 2 being in preview.
