Positioning and scope captured from the public README:

- React Doctor is described as a scanner that gives a React codebase a `0` to `100` health score plus actionable diagnostics.
- The README says it works with `Next.js`, `Vite`, and `React Native`.
- The project positions itself both as:
  - a one-shot CLI scanner
  - a GitHub Action / CI surface
  - an ESLint and Oxlint plugin
  - an agent-instruction installer for coding assistants

CLI and workflow notes captured from the README:

- The main scan command shown is:
  - `npx -y react-doctor@latest .`
- The README says findings span:
  - state and effects
  - performance
  - architecture
  - security
  - accessibility
  - dead code
- The CLI supports modes such as:
  - full-project scan
  - `--diff`
  - `--staged`
  - `--json`
  - `--score`
  - `--annotations`
  - `--explain` / `--why`

Agent and configuration notes captured from the README:

- The install flow:
  - `npx -y react-doctor@latest install`
- The README says this can write agent-specific rule files for tools such as Claude Code, Cursor, Codex, OpenCode, Windsurf, and others.
- The repo also supports a `react-doctor.config.json` file with rule ignores, file ignores, and per-file overrides.
- It can adopt existing JSON ESLint or Oxlint configuration automatically unless explicitly disabled.

CI and plugin notes captured from the README:

- The repository ships a composite GitHub Action that can post findings back to pull requests.
- The same rules are available as:
  - `react-doctor/oxlint-plugin`
  - `react-doctor/eslint-plugin`
- The README also documents a programmatic API through `react-doctor/api`.

Scoring notes captured from the README:

- The score formula is described as:
  - `100 - (unique_error_rules x 1.5) - (unique_warning_rules x 0.75)`
- The README emphasizes that score penalties count unique triggered rules rather than total violation instances.

Interpretive note:

- This source is best read as React-focused code-quality and agent-governance infrastructure. It is not only a linter or only a scoring tool; it also tries to shape future AI-written code by installing framework-specific instruction files into repositories and by exposing CI, JSON, and plugin entry points around the same rule set.
