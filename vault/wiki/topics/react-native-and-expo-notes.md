# React Native And Expo Notes

## Summary
The reviewed mobile-development slice of the export looks like a rolling toolbox for React Native and Expo work, with attention on editing rich text, motion and interaction patterns, deep linking, security review, Live Activities, bottom-sheet orchestration, and AI-assisted app creation. [src-2026-04-12-007][src-2026-04-12-023][src-2026-04-12-026][src-2026-04-12-033][src-2026-04-12-044][src-2026-04-12-048][src-2026-04-12-049][src-2026-04-12-055]

## Key Ideas
- The reviewed links combine editor infrastructure, interaction polish, and navigation primitives rather than focusing on a single feature area. Rich text editing, animation examples, sortable layouts, and stacked bottom sheets all appear as reusable UX building blocks. [src-2026-04-12-007][src-2026-04-12-023][src-2026-04-12-026][src-2026-04-12-055]
- `@ladeologun/react-native-walkthrough` adds onboarding and feature-education UI infrastructure to the toolbox: `ScreenWalkthrough` spotlights measured targets, dims the rest of the screen, auto-places tooltips, supports controlled or imperative visibility, and handles difficult overlay cases through measurement retries, `targetKey`, `collapsable={false}` guidance, and scroll preparation before highlighting off-screen targets. [src-2026-06-07-001]
- Software Mansion Labs’ `react-native-bottom-sheet` adds a concrete native implementation package to the bottom-sheet slice of the toolbox, with inline and modal sheets, controlled detents, content-based sizing, nested-scrollable negotiation, programmatic-only snap points, and position tracking for sheet-coupled UI. [src-2026-05-28-004]
- Sentry’s React Native performance article adds an optimization workflow layer to the stack by connecting Time to Interactive, Expo Router lazy loading, Expo Atlas bundle analysis, React Native DevTools profiling, React Compiler, memory-leak cleanup, 60 FPS discipline, FlashList or LegendList list rendering, fine-grained state management, and Sentry production profiling or tracing. [src-2026-05-30-001]
- `react-native-runtimes` adds a heavier New Architecture performance option by letting selected components, full screens, headless tasks, and typed functions run in named secondary Hermes runtimes, with native C++ singleton-backed shared state and runtime prewarming so expensive feeds, chats, editors, hydration jobs, or reducers do not monopolize the main JS runtime. [src-2026-06-03-004]
- `react-native-enriched-markdown` substantially expands the text-and-editor slice of the toolbox by combining native Markdown rendering, a Markdown-emitting rich text input, math, streaming, accessibility, RTL support, and a web renderer, all with explicit New Architecture positioning on native platforms. A later nightly update also adds branded text-selection styling through `selectionColor` and Android `selectionHandleColor`, reinforcing its design-system friendliness. [src-2026-04-30-001][src-2026-04-30-002]
- The follow-up repository references also reinforce the polish-and-feedback layer of the stack: `expo-gooey-toast` fits the same family of reusable feedback primitives as animated interaction libraries and notification surfaces, even though its README has not yet been fetched directly. [src-2026-04-13-004][src-2026-04-12-023]
- `toastiva` extends that same polish-and-feedback layer with morphing toast notifications built on the current React Native animation stack, including platform-specific blur handling and provider-based integration. [src-2026-05-02-004]
- `Pulsar` extends that same polish-and-feedback layer into haptics by exposing ready-made presets, custom sequence composition, and realtime gesture-driven control through a React Native Turbo Module that is explicitly compatible with worklets. [src-2026-04-26-001]
- A follow-up repository source, `expo-pretext`, reinforces the same toolbox direction around text measurement and layout by exposing pre-render height prediction, obstacle-aware text reflow, and streaming-text use cases while staying inside the standard React Native rendering tree. A later explanatory source sharpens that framing by treating the library as a broader response to virtualization pain, shape-aware flowing text, and long-standing RN text-rendering bugs, with helper components and hooks aimed at removing whole classes of workaround code. [src-2026-04-12-058][src-2026-05-01-003]
- A newer follow-up source, `react-native-nano-icons`, pushes the same performance-oriented toolbox into icon rendering by converting SVG folders into optimized icon fonts and rendering them as native glyph stacks, with explicit positioning around repeated small-icon use cases such as lists, tab bars, and inline badges. [src-2026-04-15-001]
- `react-native-capture-view` extends the same native-utility layer into screenshot and export workflows by offering Fabric-oriented capture primitives for a single view subtree, the visible screen, and full plain-`ScrollView` content, with explicit Expo dev-build and New Architecture requirements. [src-2026-04-16-001]
- The public `demos` repository by Enzo Manuel Mangano reinforces the same animation-and-polish toolbox as a living showcase of React Native interactions built with Reanimated, Gesture Handler, and Skia, organized as an Expo project rather than a one-off demo snippet. [src-2026-04-25-007]
- A smaller Reanimated playground, `reanimated-css-animations`, adds CSS-like animation-authoring reference material: its examples express keyframes and multi-stage timing data in a shape closer to browser CSS animation syntax while still running inside a React Native Reanimated setup. [src-2026-05-01-011]
- `react-native-transformer-text-input` extends the same performance-oriented utility layer into text entry by moving input transformation onto the UI thread through worklets, aiming to preserve JS-level flexibility while avoiding controlled-input lag, cursor flicker, and unstable caret behavior. [src-2026-04-25-001]
- `expo-mlkit-ocr` extends the same native-utility layer into document and image understanding by packaging on-device OCR, structured bounding-box output, and an interactive overlay component into an Expo Module that works with development builds rather than Expo Go. [src-2026-05-01-014]
- `react-native-nitro-geolocation` extends the same native-utility layer into location infrastructure by pairing a Nitro and JSI-based Modern API with a safer `/compat` migration path from the community geolocation package, while keeping its Expo dev-build support and Expo Go limitation explicit. [src-2026-05-15-001]
- A companion React Native Rewind article reinforces the same package from the ecosystem angle: it markets `react-native-nitro-geolocation` as a “one-line migration” away from the community geolocation package and repeats the narrower cached-read performance framing rather than overselling raw GPS acquisition speed. [src-2026-05-15-002]
- `react-native-nitro-biometrics` extends the same Nitro-oriented utility layer into biometrics by packaging iOS and Android authentication behind a simple Nitro module with Expo config-plugin support and explicit permission wiring for Face ID and Android biometric APIs. [src-2026-05-21-002]
- A later thoughtbot article adds a more architectural biometrics-security layer to the stack by separating three patterns: prompt-only app-level gating, OS-enforced token release from Keychain or Keystore, and hardware-backed challenge-response signing with server verification; it argues that Expo managed workflow comfortably supports the first and third-storage pattern, while the strongest cryptographic flow usually pushes teams toward bare React Native plus backend participation. [src-2026-05-27-001]
- Netguru’s fintech guide adds a regulated-product angle to the same biometrics discussion: in PSD2/SCA-style payment flows, biometric or passkey authentication should be transaction-bound through FIDO2/WebAuthn-style attestation and dynamic linking, not treated as a generic app-unlock prompt. Its React Native versus Flutter section favors React Native for JavaScript ecosystem depth, hiring, web-sharing, and native-input behavior, while treating Flutter as stronger for rendering consistency but requiring extra scrutiny around Skia-rendered sensitive inputs. [src-2026-05-31-003]
- Phone-number hinting now appears in two ecosystem shapes: `expo-phone-number-hint` offers a focused Expo wrapper around Android’s Phone Number Hint API, while `react-native-otp-verify` provides a plain React Native CLI path through a broader Android OTP and SMS Retriever library that also exposes `requestHint()`. [src-2026-05-07-002][src-2026-05-07-003]
- `expo-circular-reveal` adds a more specialized theming-motion primitive to the toolbox by packaging screenshot capture, overlay management, and native circular-mask animation into a single Expo Module for polished theme transitions triggered from a tap point. [src-2026-04-25-004]
- `TypeGPU` adds a more experimental GPU-compute and rendering angle to the mobile stack through its explicit React Native support story via `react-native-wgpu`, positioning typed WebGPU primitives as usable beyond the browser. [src-2026-04-25-005]
- `Redraw` adds a newer experimental graphics angle to the same stack by framing 2D rendering as WebGPU-native, path-aware, and analytically layered, with GPU-authored TypeScript functions and single-pass feathering or blur-style effects. [src-2026-05-12-001]
- `react-native-effects` adds a sibling experimental graphics layer built around WebGPU and worklets bundle mode, packaging shader-driven visual effects as drop-in components while exposing `ShaderView` as the reusable WGSL host primitive underneath. [src-2026-05-16-003]
- `react-native-skia-lab` adds a lighter-weight creative-coding reference layer to the same graphics toolbox by collecting Skia demos across painting, shaders, gestures, pixels, physics, and polygon visuals. [src-2026-05-15-003]
- A newer Expo UI article adds a state-management and performance angle to the same stack by framing `useNativeState` as native-shared state for SwiftUI/Compose-backed controls, especially as a way to avoid controlled-text-input lag caused by JS-thread roundtrips. [src-2026-05-13-002]
- `Ennio` adds a more experimental iOS E2E-testing layer to the stack by combining Maestro-compatible YAML flows with Hermes-Inspector and JSI-based UI discovery plus real HID actuation through `idb`, while using Expo-plugin build gating to keep the instrumentation out of Release builds. [src-2026-05-16-002]
- `freerasp-react-native` adds a mobile runtime-protection angle to the stack as Talsec’s React Native package for runtime application self-protection and in-app threat detection, though the current record is intentionally conservative because the pasted body did not match the package URL. [src-2026-05-17-007]
- `react-native-teleport` adds native re-parenting and shared-transition infrastructure to the stack by moving live views between local layout, overlay hosts, and destination screens without remounting, with the docs showing Instagram-like video transitions as a concrete recipe. [src-2026-05-20-001]
- `react-native-sandbox` adds a super-app and plugin-runtime isolation layer to the stack by running multiple React Native instances in separate JS runtimes, gating native capability access through `allowedTurboModules`, and containing plugin crashes through explicit sandbox boundaries. [src-2026-05-20-002]
- Margelo’s keyboard-handling deep dive adds a platform-mechanics layer to the mobile toolbox by explaining that iOS exposes scheduled keyboard animations while modern Android exposes per-frame insets, that Android 15 forced edge-to-edge breaks older `adjustResize` assumptions, and that `react-native-keyboard-controller` normalizes the difference through replacement `KeyboardAvoidingView`, `KeyboardAwareScrollView`, and `KeyboardStickyView` primitives. [src-2026-05-28-001]
- A short hook checklist reinforces three recurring React Native lifecycle patterns: `useKeyboardHandler` for UI-thread keyboard-height tracking, `useLastNotificationResponse` for notification deep links on cold start, and `useFocusEffect` for refetching when a screen regains navigation focus. [src-2026-06-03-005]
- The newer React Native Detour docs turn the earlier Detour landing-page mention into implementation guidance: `@swmansion/react-native-detour` wraps deferred links, Universal/App links, and custom schemes behind `DetourProvider`, supports Expo Router and React Navigation adapters, exposes `linkProcessingMode` to avoid double-processing, handles auth-gated pending links, distinguishes iOS clipboard from Android install-referrer behavior, and includes retention/custom-event analytics. [src-2026-06-06-001]
- `nativescript-expo` adds an experimental native-access direction for Expo and React Native by demonstrating NativeScript as a TurboModule or JSI-backed way to expose deep iOS APIs directly in TypeScript, including PassKit, VisionKit, PDFKit, native tab controllers, and Metal/CoreMotion effects. [src-2026-05-28-003]
- SimDeck adds an agent-driven simulator and emulator control layer for mobile work by exposing iOS and Android streaming, accessibility descriptions, tap/type/gesture control, screenshots, recordings, profiling, JS/TS test APIs, and runtime inspectors for NativeScript, React Native, Flutter, UIKit, and SwiftUI. [src-2026-05-30-002]
- Integration and platform concerns also show up directly through deep linking and security tooling. The earlier Detour source positions it as a developer-first deep linking library, while the newer repository/docs source documents the concrete React Native SDK path; RNSEC targets vulnerability discovery in React Native and Expo apps, and MobSF broadens that security slice into full static and dynamic analysis of shipped mobile binaries and runtime behavior. [src-2026-04-12-044][src-2026-06-06-001][src-2026-04-12-048][src-2026-04-25-006]
- `expo-app-blocker` extends the same native-integration theme into device-governance and blocking workflows by claiming to hide the usual complexity around Screen Time APIs, iOS extension targets, entitlements, Android overlays, and manifest wiring behind an Expo config plugin and TypeScript API. [src-2026-04-13-003]
- Expo’s EAS Gradle cache update adds a build-infrastructure optimization to the mobile stack: Android builds can reuse Gradle task outputs across runs by setting `EAS_GRADLE_CACHE=1`, with Expo reporting roughly 50% faster builds and especially strong gains for projects with many native modules. [src-2026-04-30-005]
- `expo-ruler` adds Android binary-size analysis to the Expo-specific workflow layer by wrapping Spotify Ruler in a config plugin and making its Gradle report tasks easier to adopt in Expo prebuild projects. [src-2026-05-01-013]
- The presence of Voltra and Rork extends the mobile toolbox into emerging workflow layers: JSX-driven Live Activities on one side and AI-generated Expo apps on the other. [src-2026-04-12-033][src-2026-04-12-049]
- The chat export itself reinforces that this topic was not accidental drift; React Native, Expo, and related implementation notes recur repeatedly across the captured links and short notes. [src-2026-04-12-006]
