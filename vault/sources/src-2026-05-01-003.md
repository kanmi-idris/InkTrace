# expo-pretext text-layout problem breakdown

## Summary
This source captures a user-supplied explanatory note about the problem space `expo-pretext` is meant to solve. Unlike the earlier repository-level source, this one is useful because it sharpens the library’s positioning: not just predictive text measurement, but a broader attempt to fix virtualization pain, shape-aware text flow, and a cluster of long-standing React Native text-rendering issues. [src-2026-05-01-003]

## Key Claims
- The supplied text argues that React Native has a structural text-layout problem because rendered word placement and line wrapping are not known until layout time, which complicates virtualization and advanced composition. [src-2026-05-01-003]
- It presents `expo-pretext` as a “measure before render” tool that can compute text height from a string, style, and width before the component mounts. [src-2026-05-01-003]
- The text also claims the library enables text flow around shapes, specifically calling out circular-avatar-style magazine layouts without relying on Skia or SVG workarounds. [src-2026-05-01-003]
- The supplied note says companion components such as `<SafeText>`, `<TruncatedText>`, and `<InkSafeText>` address more than eighteen long-standing React Native text-rendering bugs. [src-2026-05-01-003]
- The note describes hooks for streaming text, pinch-to-zoom layout recomputation, typewriter effects, collapsible text, and FlashList height-cache prewarming, extending the library’s scope well beyond static measurement. [src-2026-05-01-003]
- Overall, the library is framed less as a convenience utility and more as a way to remove an entire category of repeated workaround code from React Native text-heavy interfaces. [src-2026-05-01-003]
