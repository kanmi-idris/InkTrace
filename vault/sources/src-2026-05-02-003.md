# Building for Real Nigeria: Offline-First Architecture

## Summary
This source captures a detailed article-thread about building offline-first systems for unreliable network environments, using Nigeria as the motivating context. Its main value is as practical architecture guidance: local-first reads, service-worker mediation, encrypted IndexedDB storage, outbox-based background sync, delta syncing, and aggressive bandwidth discipline. [src-2026-05-02-003]

## Key Claims
- The article argues that apps targeting unstable mobile networks should default to a local-first architecture where the UI talks to local storage before the network. [src-2026-05-02-003]
- It presents service workers as a core reliability layer, especially for app-shell caching, cache invalidation, and stale-while-revalidate request handling. [src-2026-05-02-003]
- It recommends IndexedDB over `localStorage` for serious offline-first systems, and further argues that stored records should be encrypted before write rather than left in plain form on the device. [src-2026-05-02-003]
- For write operations, it recommends an outbox-based sync architecture with retry tracking, ordered replay, and idempotency keys so failed requests can be retried safely. [src-2026-05-02-003]
- For data refresh, it recommends delta syncing via a client sync cursor plus server-side `last_modified` and version metadata instead of full re-syncs. [src-2026-05-02-003]
- It also frames compression, lazy loading, responsive media delivery, and cursor pagination as baseline performance requirements rather than optional polish for bandwidth-constrained markets. [src-2026-05-02-003]
