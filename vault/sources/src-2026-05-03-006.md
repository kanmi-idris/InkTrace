# Reverse OTP in Nigeria with React Native

## Summary
This source captures a user-supplied architecture discussion about shifting SMS OTP cost to the user through a reverse OTP flow. Its main value is as a design pattern: the backend issues a challenge, the frontend opens an SMS composer, the user sends the message at their own carrier cost, and the backend verifies the resulting webhook. [src-2026-05-03-006]

## Key Claims
- The conversation argues that a user-originated SMS verification flow is more feasible than true reverse-billed SMS delivery for typical OTP use cases, especially in Nigeria. [src-2026-05-03-006]
- It frames the backend architecture around challenge generation, expiry, webhook validation, and explicit code matching rather than around sender-paid outbound OTP delivery. [src-2026-05-03-006]
- The RN-specific implementation guidance favors opening the native SMS composer through `Linking` with a prefilled number and body, with `expo-sms` mentioned as an Expo-oriented alternative. [src-2026-05-03-006]
- The source also includes regulatory and provider guidance for Nigeria, but those claims are conversational and not directly backed by primary NCC or aggregator documentation in the supplied text. [src-2026-05-03-006]
- The practical tradeoff is explicit: operator SMS costs may fall, but user friction rises because the user must actively send a message and may object to paying for verification. [src-2026-05-03-006]
