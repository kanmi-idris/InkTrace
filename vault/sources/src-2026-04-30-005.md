# Expo EAS Gradle cache for Android builds

## Summary
This source captures the supplied Expo changelog entry announcing Gradle caching for Android builds on EAS. Its main value is operational: it describes a build-performance feature that can substantially reduce repeat Android build times by reusing Gradle task outputs across builds, especially for apps with many native modules. [src-2026-04-30-005]

## Key Claims
- The changelog claims that enabling Gradle caching on EAS Android builds has produced around a 50% reduction in build times. [src-2026-04-30-005]
- The mechanism described is standard Gradle build caching: task outputs are stored and reused when inputs have not changed, instead of recomputing the tasks. [src-2026-04-30-005]
- The feature is presented as particularly effective for projects with many native modules because repeated per-module Gradle tasks can be served from cache. [src-2026-04-30-005]
- Activation is intentionally simple: set the `EAS_GRADLE_CACHE` environment variable to `1`, either through account-level environment variables or directly in `eas.json`. [src-2026-04-30-005]
- The changelog says the initial build seeds the cache and later builds restore from it, with cache keys derived from the hash of the package manager lockfile. [src-2026-04-30-005]
- Expo positions this as part of a broader Android build-caching story alongside compiler caching via `ccache` for C/C++ recompilation. [src-2026-04-30-005]
- Developers can verify cache behavior in the build logs by checking for Gradle tasks marked `FROM CACHE`. [src-2026-04-30-005]
