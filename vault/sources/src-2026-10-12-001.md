# Biometrics Don’t Authenticate Anyone

## Summary
Pelumiogundipe argues that a local biometric prompt is not proof to a remote server. The article recommends enrolling a device key after full login, then using OS-gated signatures over fresh server challenges. It also describes a local Expo SecureStore option and server-side safeguards. [src-2026-10-12-001]

## Key Claims
- The author says a JavaScript `success` boolean can be altered on a compromised client and does not give the server proof of a biometric check. The package README independently warns against using `simplePrompt()` for server login and recommends signatures instead. [src-2026-10-12-001] [src-2026-10-12-002]
- The proposed flow enrolls a private/public key pair after full login, stores the private key on-device, registers the public key with the server, and signs a fresh challenge for login or a transfer. [src-2026-10-12-001] [src-2026-10-12-002] [src-2026-10-12-005]
- The article says challenges should be random, single-use, short-lived, and deleted after use. It recommends fresh signatures for high-value actions and key removal after password changes or lost-device reports. [src-2026-10-12-001]
- Apple documents `biometryCurrentSet` as an access rule for currently enrolled biometrics and says changes to the enrolled set invalidate the protected item. [src-2026-10-12-004]
- Android documents cryptographic operations through `BiometricPrompt.CryptoObject`, including `Signature`, and auth-per-use keys for high-value actions. It also supports device-credential fallback, which the app must configure. [src-2026-10-12-005]
- Expo says values protected with `requireAuthentication` become inaccessible after biometric setting changes. Its docs describe platform differences and warn against relying on SecureStore as the only copy of critical data. [src-2026-10-12-003]
- The article's maintenance claim concerns the unscoped package. npm showed `react-native-biometrics` v3.0.1, published four years ago. A separate scoped package has a newer release, but it is not the same package. [src-2026-10-12-002] [src-2026-10-12-006]

## Notes
A valid signature shows that the registered key signed the challenge. The article does not establish that the server receives biometric data or can identify which human used the device.
