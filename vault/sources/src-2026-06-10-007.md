# Moving away from @expo/vector-icons

## Summary
Expo’s migration article turns the earlier deprecation signal into explicit guidance: Expo now recommends moving from `@expo/vector-icons` to the icon-pack-specific `@react-native-vector-icons/*` packages because they now work across Expo apps, including Expo Go, integrate directly with `expo-font`, reduce aliasing complexity, and can materially shrink shipped bundle and asset size. Expo’s linked repro app reportedly dropped by about `4 MB` after changing the dependency and import path. [src-2026-06-10-007]

## Key Claims
- Expo recommends switching from `@expo/vector-icons` to the latest icon-pack-specific packages under `@react-native-vector-icons`. [src-2026-06-10-007]
- Those packages now integrate directly with `expo-font`, call its native font-loading API when needed, and work in Expo Go, development builds, and across platforms. [src-2026-06-10-007]
- Expo no longer wants to maintain `@expo/vector-icons` because the wrapper adds aliasing and maintenance complexity while duplicating ecosystem work outside Expo’s core platform scope. [src-2026-06-10-007]
- Expo says apps may accidentally ship all icon fonts through `@expo/vector-icons`, and its repro app reduced shipped bundle and asset payload size by around `4 MB` after migrating. [src-2026-06-10-007]
- The migration path includes a codemod, an `expo doctor` verification step, explicit `expo-font` setup, and a warning not to add `node_modules/@react-native-vector-icons/` font paths to the `expo-font` config plugin because that causes a build error. [src-2026-06-10-007]
- Expo warns that mixing old and new icon package families or versions can cause icons to render incorrectly, and says it added a doctor warning to detect these package-mixing issues. [src-2026-06-10-007]
