# Expo SecureStore authentication and persistence behavior

## Summary
Expo SecureStore encrypts local key-value data. With `requireAuthentication: true`, Expo says protected data becomes inaccessible after biometric settings change. The API has platform-specific prompt behavior and is not a server-verifiable signature. [src-2026-10-12-003]

## Key Claims
- Expo says Android stores values in SharedPreferences encrypted with Android Keystore, while iOS uses Keychain services. [src-2026-10-12-003]
- Expo says Android requires authentication for operations using `requireAuthentication`. On iOS, the prompt appears when reading or updating an existing value, not when initially saving it. [src-2026-10-12-003]
- Expo says values protected by `requireAuthentication` become inaccessible after biometric settings change. [src-2026-10-12-003]
- Expo says `requireAuthentication` is not supported in Expo Go when biometric authentication is available. It also warns not to rely on SecureStore as the only source of critical, irreplaceable data. [src-2026-10-12-003]
- The Medium article says `getItemAsync` returns `null` after biometric changes. Expo's docs say “inaccessible”; test the actual return or error behavior in the target SDK version. [src-2026-10-12-001] [src-2026-10-12-003]
