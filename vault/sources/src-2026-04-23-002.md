# Bun + Elysia production-readiness discussion for high-stakes infrastructure

## Summary
This source captures a user-supplied discussion thread about whether Bun and Elysia are appropriate for a high-stakes, government-facing API gateway. The thread is useful as anecdotal operational evidence about perceived runtime maturity, but it should not be treated as a rigorous benchmark or security assessment because the current record is grounded in pasted discussion text rather than a verified canonical thread URL. [src-2026-04-23-002]

## Key Claims
- The initiating question frames Bun and Elysia as attractive because of performance claims and developer experience, especially Bun's built-in SQL support and Elysia's API ergonomics. [src-2026-04-23-002]
- A recurring caution in the thread is that Bun may still carry unacceptable operational risk for critical infrastructure because commenters reported or worried about segmentation faults, memory leaks, worker instability, compatibility gaps, and memory-safety exposure in low-level implementation layers. [src-2026-04-23-002]
- Several commenters argued that older or more established stacks such as Node, Fastify, Go, Rust, Java, C#, or Elixir are safer choices when approval processes, long-term maintenance, and operational predictability matter more than raw benchmark wins. [src-2026-04-23-002]
- The thread also suggests a split view between Bun and Elysia: some commenters were skeptical of Bun as the runtime while still noting that Elysia can target multiple JavaScript runtimes, which makes portability or fallback-to-Node strategies more appealing. [src-2026-04-23-002]
- A minority of comments were positive about deploying Bun and Elysia in production, especially for API gateway or backend-for-frontend roles with resiliency layers and relatively simple logic. [src-2026-04-23-002]
- The strongest practical takeaway from the thread is not that Bun is proven unsafe, but that high-assurance adopters should assume higher maturity risk and demand an escape hatch, deeper validation, and stricter operational testing than they might for more established runtimes. [src-2026-04-23-002]
