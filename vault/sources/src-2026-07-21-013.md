# How Worklets Bundle Mode accidentally fixed Hermes V1 memory regression

## Summary
Technical deep-dive by Tomasz J. Żelawski explaining how Hermes V1's dynamic `eval` debug metadata allocated 512KB per worklet function in production builds, leading to high memory consumption in Reanimated apps. Provides four solutions: Worklets Bundle Mode, pre-compiled bytecode for legacy eval mode, pinning Hermes to version 0.15, or waiting for React Native 0.87.

## Key Claims
- Hermes V1 allocates 512KB of debug metadata for every function evaluated at runtime via dynamic `eval`. [src-2026-07-21-013]
- Reanimated's *Legacy Eval Mode* evaluates worklet functions as code strings on the UI thread runtime, incurring a >50MB startup memory penalty for 100+ worklets. [src-2026-07-21-013]
- In large applications (e.g. Expensify with >1,000 worklets), unpatched dynamic evaluation can consume up to 0.5GB of memory if all worklets are evaluated. [src-2026-07-21-013]
- Worklets *Bundle Mode* (Worklets 0.10.0+) exposes the complete JS bytecode bundle to secondary runtimes via `mmap` lazy loading, resolving the memory regression at near-zero overhead. [src-2026-07-21-013]
- Upstream Hermes fixed the regression in `facebook/hermes#2090` (backported to Hermes 0.15 / 250829098.0.15 and shipping natively in React Native 0.87 on Aug 8, 2026). [src-2026-07-21-013]
