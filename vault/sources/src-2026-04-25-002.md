# metadata-gen

## Summary
This source captures the supplied repository summary and README-style documentation for `metadata-gen`, a local CLI that scans an existing project for branding and design signals, then generates metadata images and a full favicon set without relying on API keys or external services. Its main positioning is speed and convenience: infer project metadata, preview several OG-image options locally, and write the chosen assets directly into the repo. [src-2026-04-25-002]

## Key Claims
- The tool presents itself as a local-only generator for metadata images and favicon assets, explicitly stating that it does not require API keys or external services. [src-2026-04-25-002]
- The workflow is split into `npx metadata-gen init`, which scans the project root and writes `metadata.config.json`, and `npx metadata-gen`, which renders variants, starts a local preview server, and opens the browser. [src-2026-04-25-002]
- The init step is described as scanning for title, tagline, colors, and logo using static read-only inspection of files such as `package.json`, `README.md`, CSS custom properties, Tailwind config, design-token JSON, and common asset locations. [src-2026-04-25-002]
- The generation step claims to produce three Open Graph image options at 1200x630 plus a complete favicon set including ICO, SVG with light or dark mode support, PNGs, and a webmanifest. [src-2026-04-25-002]
- The preview interface is described as allowing refinement of colors, text, and logo visibility before downloading the results directly into `public/metadata/` inside the project. [src-2026-04-25-002]
- The documented output set includes a chosen `og.png`, multi-size favicon files, Apple and Android touch icons, and `site.webmanifest`, with output-directory override support via CLI flag. [src-2026-04-25-002]
- The source also claims that if no logo is found, the tool falls back to generating a lettermark from the first letter of the title. [src-2026-04-25-002]
