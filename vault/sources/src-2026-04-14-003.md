# Four Principles of Writing Good Code

## Summary
This source defines good frontend code as code that is easy to modify and deploy. It organizes that goal into four evaluation criteria: readability, predictability, cohesion, and coupling, while stressing that those values can conflict and must be balanced intentionally. [src-2026-04-14-003]

## Key Claims
- Good frontend code is code that remains easy to modify when new requirements arrive, and that property can be evaluated through readability, predictability, cohesion, and coupling. [src-2026-04-14-003]
- Readability improves when code that does not execute together is separated, implementation details are abstracted appropriately, and the number of simultaneous contexts for the reader is reduced. [src-2026-04-14-003]
- Predictability improves when names, parameters, and return types communicate behavior clearly and consistently, and when hidden logic is exposed. [src-2026-04-14-003]
- Cohesion improves when code that should change together is stored and structured together, even if that sometimes requires abstraction that reduces readability. [src-2026-04-14-003]
- Lower coupling limits the blast radius of changes, and the source recommends strategies such as narrower responsibilities, tolerated duplication, and avoiding props drilling. [src-2026-04-14-003]
