# The Vertical Codebase

## Summary
This source argues that codebases should be structured vertically by functionality rather than horizontally by technical type. The central claim is that grouping by verticals increases cohesion, reduces unnecessary navigation, and creates boundaries that benefit both humans and AI agents working in the codebase. [src-2026-04-14-001]

## Key Claims
- Horizontal structures such as `components`, `hooks`, `types`, and `utils` scale poorly because they split logically related code across technical buckets. [src-2026-04-14-001]
- A better alternative is to group code into verticals based on what it does, allowing components, hooks, types, and utilities for the same area to live together. [src-2026-04-14-001]
- Shared code can still fit the model by becoming its own vertical, such as a `pageFilters` vertical or a `design-system` vertical. [src-2026-04-14-001]
- Boundaries are still necessary, and the article points to monorepos, package exports, Nx, or `eslint-plugin-boundaries` as ways to make public interfaces explicit and prevent uncontrolled coupling. [src-2026-04-14-001]
- The article also claims that AI agents need the same fundamentals humans need, including boundaries, constraints, good project structure, linting, TypeScript, and fast feedback loops. [src-2026-04-14-001]
