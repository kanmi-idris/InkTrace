# Seven cool JavaScript libraries You should know about

## Summary
Neciu Dan’s JavaScript libraries article is a practical frontend tooling checklist covering dead-code detection, URL-state management, TypeScript pattern matching, OpenAPI client generation, runtime validation, linting/formatting consolidation, and safer HTTP requests. The core stack is Knip, Nuqs, ts-pattern, Orval, Zod, Biome, and ofetch. [src-2026-05-31-004]

## Key Claims
- Knip is positioned as a dead-code and dependency-cleanup tool that can find unused files, exports, dependencies, and devDependencies, with `--production` and CI usage called out as high-leverage practices. [src-2026-05-31-004]
- Nuqs is positioned as a URL-state layer for React applications, making pagination, filters, sorting, modal state, and tabs refresh-safe and shareable through query parameters instead of parallel React-state synchronization. [src-2026-05-31-004]
- ts-pattern is positioned as a safer TypeScript control-flow tool because `.exhaustive()` turns missing discriminated-union cases into build-time failures. [src-2026-05-31-004]
- Orval is positioned as OpenAPI-driven frontend infrastructure that generates typed API clients, query hooks, schemas, and mocks so backend schema drift becomes a compile-time problem. [src-2026-05-31-004]
- Zod is positioned as the mainstream schema-as-type runtime validation layer, especially for parsing API responses, forms, and localStorage at application boundaries, while Valibot is noted as a smaller but less ecosystem-rich alternative. [src-2026-05-31-004]
- Biome is positioned as a fast Rust-based replacement for many ESLint-plus-Prettier setups, with caveats around niche ESLint plugin coverage and possible staged migration. [src-2026-05-31-004]
- ofetch is positioned as a lightweight `fetch` wrapper that centralizes JSON handling, non-2xx errors, retries, timeouts, base URLs, and interceptors across browser, Node, Workers, and Bun runtimes. [src-2026-05-31-004]
