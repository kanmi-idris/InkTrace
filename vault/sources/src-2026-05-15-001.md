# react-native-nitro-geolocation

## Summary
This source captures the public `react-native-nitro-geolocation` repository page. It is best understood as New Architecture geolocation infrastructure for React Native: a Nitro and JSI-positioned native location module that pairs a typed Modern API with a safer `/compat` migration layer for teams coming from the community geolocation package. [src-2026-05-15-001]

## Key Claims
- The package positions itself as a modern iOS and Android geolocation module for React Native `0.75+` and New Architecture apps. [src-2026-05-15-001]
- Its most practical adoption story is the two-layer API design: use `/compat` first for a low-risk migration, then move to the Modern API when explicit ownership of permissions, cache reads, settings, and hooks becomes worthwhile. [src-2026-05-15-001]
- The README explicitly ties its performance story to Nitro and JSI by reducing Bridge overhead, while also being careful to say the benchmark only reflects cached reads and JS-to-native call costs rather than faster GPS acquisition itself. [src-2026-05-15-001]
- The repository is also clear about platform boundaries: Expo development builds are supported, Expo Go is not, managed Expo apps without native rebuilds should use `expo-location`, and web is not yet supported in `v1.2.x`. [src-2026-05-15-001]
- Beyond basic latitude and longitude reads, the Modern API expands into geocoding, reverse geocoding, heading, coarse-vs-precise accuracy handling, Android settings resolution, and development-time mocking through an optional Rozenite plugin. [src-2026-05-15-001]
