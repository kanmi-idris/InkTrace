# How a Kotlin compiler plugin cut Android time to first render

## Summary
Expo’s SDK 56 article describes a build-time performance optimization for Expo Modules on Android: a Kotlin compiler plugin built on the K2 compiler API replaces reflection-heavy runtime metadata work with compile-time substitutions. Expo reports 70% faster module initialization, about 6x faster Record conversions, and a 30% reduction in Android time to first render, all without requiring app-level code changes. [src-2026-06-10-005]

## Key Claims
- Expo SDK 56 ships a Kotlin compiler plugin that strips reflection-heavy work from Expo Modules on Android. [src-2026-06-10-005]
- The article reports three main outcomes: 70% faster module initialization, roughly 6x faster Record conversions versus SDK 55, and a 30% lower Android time to first render. [src-2026-06-10-005]
- The remaining reflection cost before this change came mainly from two areas: runtime type-parameter reconstruction and Record conversion that depended on Kotlin reflection plus `@Metadata` parsing. [src-2026-06-10-005]
- Expo rejected conventional code generation approaches such as kapt, KSP, and standalone codegen because they add generated project surface area, complicate debugging, and cannot surgically rewrite existing code paths. [src-2026-06-10-005]
- Kotlin 2.0’s K2 compiler plugin API changed the tradeoff by allowing Expo to modify IR during compilation, making targeted substitutions possible without raw bytecode patching or parallel generated source layers. [src-2026-06-10-005]
- The plugin replaces calls such as `typeDescriptorOf<T>()` with direct references to precomputed type descriptors, shifting metadata work from runtime to compile time. [src-2026-06-10-005]
- App developers benefit automatically, while module authors can unlock the Record-side speedup with a minimal annotation change. [src-2026-06-10-005]
