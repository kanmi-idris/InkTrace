# Liquid DOM

## Summary
This source captures the public Liquid DOM repository. It is best understood as experimental rendering-stack and layout-engine tooling: a WebGPU-focused liquid-glass system organized as a monorepo with a renderer-agnostic layout engine, an imperative DOM-backed core, React bindings, and adapters for Three.js WebGPU and React Three Fiber. [src-2026-05-24-001]

## Key Claims
- Liquid DOM positions itself not as one package but as a layered architecture spanning layout, rendering core, React bindings, Three integration, and R3F integration. [src-2026-05-24-001]
- The split between `@liquid-dom/layout` and the higher-level rendering packages makes the layout engine itself a reusable architectural artifact, not just an implementation detail. [src-2026-05-24-001]
- The project is explicitly tied to modern browser graphics capabilities, especially WebGPU, and for DOM-backed content it depends on experimental HTML-in-Canvas behavior currently gated behind Chrome flags. [src-2026-05-24-001]
- The repository is therefore useful as both a visual-effects reference and a case study in how to layer renderer-agnostic layout with multiple rendering and framework adapters. [src-2026-05-24-001]
- The separate showcase URL strengthens the project signal by confirming a live demo surface exists in addition to the codebase and README. [src-2026-05-24-001]
- The `VideoControlsDemo.tsx` showcase file adds concrete evidence that the React layer supports animated, stateful compositions over media-like surfaces using glass primitives, layout containers, HTML embedding, and spring-driven interactions. [src-2026-05-24-001]
