# A gentle introduction to TanStack Query

## Summary
This source captures Neciu Dan’s article on TanStack Query. It is best understood as React data-fetching architecture guidance: an explanation of why shared query caches, stable query keys, cancellation signals, freshness controls, and reusable query option factories outperform ad hoc `useEffect`-driven fetching as applications grow. [src-2026-05-26-001]

## Key Claims
- The article frames TanStack Query as a response to three recurring problems in hand-rolled React fetching: repeated boilerplate, race conditions around in-flight requests, and lack of cache persistence across component lifecycles. [src-2026-05-26-001]
- The article's introductory posture is deliberate: the author says the piece was motivated by seeing experienced React audiences vary sharply in TanStack Query familiarity, so it explains the basics before moving into scaling patterns. [src-2026-05-26-001]
- It emphasizes that `queryKey` does more than identify data conceptually; it enables shared caching, request deduplication, and background refetch behavior across components. [src-2026-05-26-001]
- The article treats several defaults and options as foundational mental models for real use: retry behavior, abort signals, `enabled` versus `skipToken`, and especially the distinction between `staleTime` and `gcTime`. [src-2026-05-26-001]
- Its strongest scaling advice is structural: prefer `queryOptions` factories and domain-grouped query definitions over custom wrapper hooks so the same typed query contract can be reused in components, suspense flows, prefetching, and loaders. [src-2026-05-26-001]
- It also pushes the architecture further by recommending generated CRUD query layers from OpenAPI via Orval and by documenting advanced patterns like dynamic parallel queries, infinite queries, and batched invalidation for overlapping optimistic mutations. [src-2026-05-26-001]
