# ShadowCat

## Summary
ShadowCat is a single-file browser tool for offline optical data transfer between devices using QR codes. Its main value is resilience in degraded-device scenarios: if radios such as BLE or NFC are unavailable but cameras and browsers still work, text or chunked files can still move through a QR frame loop with receiver-side missing-chunk tracking and CRC verification. [src-2026-06-03-001]

## Key Claims
- The README positions ShadowCat for old phones whose radios are dead but whose cameras and browsers still work, making it an offline fallback transport rather than a normal high-throughput sync mechanism. [src-2026-06-03-001]
- File sending is implemented as a repeated QR sequence of one header plus 1-indexed data chunks, with configurable chunk size, FPS, ECC level, optional gzip compression, and manual controls for pausing or resending specific frames. [src-2026-06-03-001]
- The `QRX1` protocol uses a header frame carrying total frames, flags, filename, on-wire size, and original-byte CRC, followed by data frames containing base64 chunks. [src-2026-06-03-001]
- Receiver behavior is designed for lossy optical transfer: it autodetects headers, ignores duplicate chunks, tracks missing chunk indexes, refuses unknown flags, verifies CRC, and only offers download when the file is complete. [src-2026-06-03-001]
- The repository includes a full protocol spec, Python encoder/decoder tools, JavaScript protocol tests extracted from the HTML, and a shared golden fixture to detect drift between implementations. [src-2026-06-03-001]
- Practical constraints are explicit: camera access generally needs HTTPS or localhost, iOS Safari needs HTTPS for cross-device camera use, dense QR frames can overflow, and the README’s rough throughput example is under 1 KB/s raw. [src-2026-06-03-001]
