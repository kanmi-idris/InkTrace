# nanoMuse privacy and data controls

## Summary
The project's privacy policy says nanoMuse stores most agent data locally when users avoid the cloud relay. It also describes account metadata and two default-on cloud controls for some signed-in users: model-improvement data collection and conversation sync. Actual data flow depends on user settings and provider choice. These are project statements, not a verified audit. [src-2026-10-10-002]

## Key Claims
- The policy says local app use has no analytics, crash reporting, or telemetry. If users sign in to the relay, it says the service records account, request, client, and network-address metadata. [src-2026-10-10-002]
- The policy says model-improvement collection stores chat text, model answers, and selected tool calls while enabled. It says it excludes system prompts, tool results, and media content. It says the switch is on by default for accounts created on the cloud relay from version 0.9 onward. It also says users can turn it off and delete prior data. [src-2026-10-10-002]
- The policy says conversation sync is on by default for signed-in users from relay 0.19. It describes storing message text and metadata, but not attached files, images, or tool results. Users can disable sync and delete stored conversations. [src-2026-10-10-002]
- The policy says software installation can run without prior approval. It says deletion and sending may have remembered approvals, while purchases and transfers require approval at the time. [src-2026-10-10-002]
- The policy says accessibility permission starts off and passwords, codes, and card numbers are not typed by the agent. These are vendor descriptions and were not tested. [src-2026-10-10-002]
