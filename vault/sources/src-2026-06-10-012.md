# DESIGN.md format specification

## Summary
The `DESIGN.md` spec defines an open, agent-readable design-system document format that combines structured token frontmatter with ordered human-readable guidance. Its core proposal is that machine-readable tokens and prose rationale should live together in one plain-text source of truth so humans, AI agents, and tooling can share the same design intent without collapsing everything into either raw tokens or vague narrative. [src-2026-06-10-012]

## Key Claims
- `DESIGN.md` is defined as a self-contained plain-text representation of a design system that both humans and AI can understand and refine. [src-2026-06-10-012]
- The format splits into optional YAML frontmatter for normative design tokens and markdown body sections for contextual guidance and rationale. [src-2026-06-10-012]
- The token model borrows from the Design Token JSON spec and supports typed groups such as colors, typography, spacing, rounded scales, and component tokens, plus `{path.to.token}` references. [src-2026-06-10-012]
- The spec explicitly positions the format as convertible to or from other design-system representations such as `tokens.json`, Figma variables, and Tailwind theme configs. [src-2026-06-10-012]
- The markdown body follows a standardized section order covering overview, color, typography, layout, elevation, shape, components, and explicit do-or-don't guidance, keeping design rationale structured rather than freeform. [src-2026-06-10-012]
- The deeper design argument in the spec is that prose and tokens serve different roles: tokens define exact values, while prose explains intent, emotional tone, and application rules. [src-2026-06-10-012]
