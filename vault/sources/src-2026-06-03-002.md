# Diffshub / On Rendering Diffs

## Summary
Diffshub and Pierre’s “On Rendering Diffs” article document browser-scale diff rendering as an infrastructure problem: large review surfaces need virtualization, layout estimation, scroll anchoring, memory control, DOM pooling, deferred syntax highlighting, and browser-specific fallbacks. The user-supplied Diffshub demo also shows DOM-safe text diffs through CSS Custom Highlight API ranges rather than injected markup. [src-2026-06-03-002]

## Key Claims
- Code review surfaces multiply ordinary file-rendering costs across many files, so rendering, processing, and memory become connected constraints rather than isolated optimizations. [src-2026-06-03-002]
- `CodeView` is presented as a virtualization-first component for reviewing code and diffs at scale, with the practical goal that product teams should be able to “just render any diff” without rebuilding the review surface from scratch. [src-2026-06-03-002]
- The “Inverse Sticky Technique” preserves native scrolling while making blanking difficult: if JavaScript falls behind, the rendered region sticks to the viewport edge instead of scrolling away and exposing empty space. [src-2026-06-03-002]
- Large-diff layout is handled through cheap first-pass estimates, internal line-range virtualization, cached position-to-line checkpoints, measured deltas, and custom scroll anchoring after disabling browser anchoring with `overflow-anchor: none`. [src-2026-06-03-002]
- Memory optimizations include detaching parsed strings from giant patch inputs, pooling Shadow DOM wrappers, and using shared options state instead of rewriting configuration across many file or diff instances. [src-2026-06-03-002]
- Syntax highlighting is deferred so plain text renders first while worker-owned Shiki highlighters and an LRU cache progressively enhance visible code without blocking the main review surface. [src-2026-06-03-002]
- The Diffshub text comparison demo uses flattened text and CSS Custom Highlight API ranges, including `::highlight(highlight-diff-base)` and `::highlight(highlight-diff-compare)`, so mismatches can be painted across real text-node ranges without injecting markup. [src-2026-06-03-002]
- The demo distinguishes positional diffs from LCS edit-script diffs: positional comparison marks downstream text after insertions, while LCS aligns equal substrings and paints only actual insertions or deletions. [src-2026-06-03-002]
