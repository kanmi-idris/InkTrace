# Cloudflare R2 getting started + user-supplied HLS video hosting walkthrough

## Summary
This source combines the official Cloudflare R2 getting-started docs with user-supplied architecture notes about hosting and delivering HLS video from R2. It is best understood as storage-and-delivery infrastructure guidance: R2 provides the low-egress object-storage layer and multiple access modes, while the accompanying workflows argue that serious video delivery should use adaptive segmented outputs rather than serving raw MP4 files directly, whether those outputs are generated locally with `ffmpeg` or temporarily outsourced to Cloudflare Stream before being moved into R2. [src-2026-05-21-001]

## Key Claims
- The official docs position Cloudflare R2 as object storage for large unstructured data with multiple access patterns, including Workers, S3-compatible APIs, CLI tools, and dashboard management. [src-2026-05-21-001]
- The pricing and product framing make egress economics a central differentiator, which is why R2 is attractive for media-serving workflows. [src-2026-05-21-001]
- The user-supplied walkthrough argues that large-video hosting should generally avoid serving raw MP4 blobs directly and instead prefer HLS playlists with segmented chunks and multiple quality levels. [src-2026-05-21-001]
- The practical workflow described is local `ffmpeg` encoding to HLS, optional thumbnail extraction, upload to R2 via S3-compatible tooling, and database-backed playlist or asset metadata in the application layer. [src-2026-05-21-001]
- A later user-supplied implementation note adds a second pattern: use Cloudflare Stream as a temporary transcoding service to generate multiple video qualities, then move the generated outputs into R2 and delete the Stream copy. [src-2026-05-21-001]
- The broader architectural value is that R2 can serve as the cheap object-storage substrate while adaptive bitrate behavior and media preprocessing are handled outside R2 itself. [src-2026-05-21-001]
