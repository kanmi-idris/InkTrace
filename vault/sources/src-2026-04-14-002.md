# Keeping Files That Are Modified Together in the Same Directory

## Summary
This source argues that files which change together should be stored together, because directory structure should make dependencies obvious and reduce leftover code when features are removed. It contrasts type-based folders with domain-oriented grouping as a way to improve cohesion. [src-2026-04-14-002]

## Key Claims
- Organizing a codebase only by technical type, such as `components`, `hooks`, and `utils`, makes it harder to understand which files depend on each other. [src-2026-04-14-002]
- Grouping feature-specific files into domain directories improves cohesion and makes dependency boundaries easier to spot, including suspicious cross-domain imports. [src-2026-04-14-002]
- A domain-oriented structure also makes deletion cleaner, because an entire feature’s related files can be removed together instead of leaving unused code behind. [src-2026-04-14-002]
