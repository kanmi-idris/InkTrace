# Cap

## Summary
This source captures the public GitHub repository page for `tiagozip/cap`, a self-hosted CAPTCHA alternative built around proof-of-work and JavaScript instrumentation rather than visual puzzles. Its main value is as a privacy-first anti-abuse primitive: it aims to protect web properties and APIs without outsourcing challenge telemetry to a third-party CAPTCHA provider. [src-2026-04-26-002]

## Key Claims
- Cap presents itself as a lightweight, modern CAPTCHA alternative that uses SHA-256 proof-of-work and JavaScript instrumentation challenges instead of image-based tests. [src-2026-04-26-002]
- The captured README emphasizes privacy and accessibility, claiming no images, no tracking, zero dependencies, and broad runtime compatibility. [src-2026-04-26-002]
- The project can reportedly run on any JavaScript runtime or in a standalone Docker-based mode, which suggests deployment flexibility beyond a single hosting model. [src-2026-04-26-002]
- The README positions Cap as much smaller than hCaptcha, explicitly claiming an approximate size of 20kb and a roughly 250x smaller footprint. [src-2026-04-26-002]
- The page also highlights programmatic/background solving and machine-to-machine protection as supported patterns, extending the tool beyond a visible widget-only interaction model. [src-2026-04-26-002]
- Cap is explicitly framed as an alternative to reCAPTCHA, hCaptcha, and Cloudflare Turnstile, with self-hosting and lack of vendor telemetry as key differentiators. [src-2026-04-26-002]
- The visible repository layout includes separate `server`, `standalone`, `wasm`, and `widget` directories, which suggests the project spans challenge generation, client widget delivery, and deployment packaging. [src-2026-04-26-002]
