# Biometrics authentication for your mobile app

## Summary
This source captures thoughtbot’s biometrics-authentication article. It is best understood as mobile security architecture guidance for React Native and Expo teams: a comparison of three approaches that differ not just in DX, but in where biometric enforcement actually happens, how tightly secrets are bound to biometric success, what backend work is required, and how resistant the result is to runtime patching or credential replay. [src-2026-05-27-001]

## Key Claims
- The article’s main contribution is the security distinction between three layers of enforcement: app-level prompt gating, OS or hardware-gated token release, and hardware-backed challenge-response signing with server verification. [src-2026-05-27-001]
- It treats prompt-only flows as convenience UX rather than strong protection because biometric success and token retrieval remain separate operations that can be bypassed in hostile runtimes. [src-2026-05-27-001]
- It frames hardware-backed key-pair signing as the strongest model, because successful biometric authentication is cryptographically coupled to a server-verifiable challenge-response flow. [src-2026-05-27-001]
- It presents OS-enforced protected storage as the practical middle path: stronger than prompt-only checks, compatible with Expo managed workflow, but still lacking server-side proof that a biometric event occurred. [src-2026-05-27-001]
- The article also sharpens the Expo-versus-bare distinction by showing that Expo’s standard managed APIs comfortably support prompt-only and protected-storage approaches, while challenge-signing flows push teams toward bare React Native plus backend participation. [src-2026-05-27-001]
