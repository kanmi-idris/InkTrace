# QuantMind repository

## Summary
`LLMQuant/quant-mind` is a Python framework for turning unstructured quantitative-finance material into typed knowledge artifacts that can later be searched or reasoned over. Its current public shape is best understood as a domain-specific ingestion and retrieval stack: fetch papers or related content, normalize them into structured financial knowledge objects, then support downstream retrieval modes such as embeddings, RAG, DeepResearch, or Data MCP rather than shipping a direct trading engine. [src-2026-06-10-002]

## Key Claims
- QuantMind presents itself as an intelligent knowledge extraction and retrieval framework for quantitative finance, explicitly targeting papers, news, blogs, reports, and SEC filings. [src-2026-06-10-002]
- The README frames the system as a two-stage architecture: knowledge extraction first, then intelligent retrieval over the resulting structured knowledge base. [src-2026-06-10-002]
- The extraction stage is designed around source connectors, parsing, tagging, orchestration, quality control, and deduplication rather than around a single monolithic pipeline step. [src-2026-06-10-002]
- The retrieval stage is framed as embeddings plus multiple solution scenarios, including DeepResearch, RAG, and Data MCP, which suggests the project is intended as a reusable finance-research substrate rather than one fixed application. [src-2026-06-10-002]
- The currently documented implementation surface is strongly flow-oriented: `quantmind.flows` exposes `paper_flow` and `batch_run`, while `quantmind.magic` can resolve free-form natural-language requests into typed flow inputs and config objects via the OpenAI Agents SDK. [src-2026-06-10-002]
- `PaperInput` is modeled as a discriminated union over arXiv IDs, HTTP URLs, local files, raw text, and DOI identifiers, which indicates the framework already treats heterogeneous research sources as one normalized entry problem. [src-2026-06-10-002]
- The internal data model is explicit and typed: the knowledge layer defines artifacts such as `Paper`, `PaperKnowledgeCard`, `News`, `Earnings`, `Factor`, and `Thesis`, with base abstractions for flattened, tree, and graph-shaped knowledge. [src-2026-06-10-002]
- Its dependency stack and project config show strong emphasis on LLM-driven extraction plus document preprocessing, using `openai`, `openai-agents`, `litellm`, `pymupdf`, `trafilatura`, optional `marker-pdf`, and optional `sentence-transformers`. [src-2026-06-10-002]
- The README’s larger promise of ingesting all quantitative-finance research into a semantic knowledge graph is more ambitious than the concrete public implementation evidence captured here, which is clearest around paper ingestion and typed research-object construction. [src-2026-06-10-002]
