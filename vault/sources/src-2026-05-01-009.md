# Claude Code .env Security Config Advisory

## Summary
This source is a user-supplied advisory post about protecting secrets while using Claude Code. Its main value is not as definitive evidence about Claude Code internals, but as a practical threat-modeling checklist: block direct reads of secret files, reduce leakage through command output and search tooling, and add repository-level guardrails such as dummy test credentials and pre-commit secret scanning. [src-2026-05-01-009]

## Key Claims
- The supplied post argues that advisory instructions in `CLAUDE.md` are weaker than hard deny rules in Claude Code `settings.json`, because deny rules are framed as the actual enforcement boundary for file access. [src-2026-05-01-009]
- The post identifies three main secret-exposure paths during agent-assisted coding: direct file reads, runtime output capture from executed commands, and grep or search output that surfaces matched secrets. [src-2026-05-01-009]
- The strongest practical recommendation in the post is to deny read or write access to `.env` files, key material, cloud-credential directories, and similar paths at the tool-permission layer rather than relying only on prompt-level instructions. [src-2026-05-01-009]
- The post also recommends defensive workflow changes outside the agent itself, especially dummy-valued `.env.test` files, pre-commit secret scanning, `.gitignore` hygiene, and optionally container isolation for high-sensitivity work. [src-2026-05-01-009]
- The post makes stronger claims about Claude Code and Anthropic behavior, including references to secrets entering conversation logs and to a GitHub issue, but the supplied material does not include direct links or primary evidence for those claims. [src-2026-05-01-009]
