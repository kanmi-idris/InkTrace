# react-native-runtimes

## Summary
`react-native-runtimes` is a Margelo and Callstack React Native New Architecture project that lets selected components, screens, headless tasks, and typed functions run in named secondary Hermes runtimes. Its goal is to keep navigation, gestures, input, and frame-critical UI responsive when expensive feeds, chats, editors, hydration jobs, reducers, or business logic would otherwise monopolize the main JavaScript runtime. [src-2026-06-03-004]

## Key Claims
- The project is explicitly for React Native New Architecture apps using Hermes; it does not target the legacy architecture or non-Hermes engines. [src-2026-06-03-004]
- `OnRuntime` wraps a component so Metro can rewrite it into a threaded runtime boundary with little manual registration. [src-2026-06-03-004]
- `ThreadedScreen` and `threadedComponent` support full-screen routes that live on secondary runtimes, while `ThreadedRuntime.prewarm` can start a runtime before navigation to reduce cold-start lag. [src-2026-06-03-004]
- Headless tasks and cross-runtime function calls let teams move cache hydration, decoding, reducers, or compute-heavy business logic away from the main runtime. [src-2026-06-03-004]
- `@react-native-runtimes/state` exposes a native C++ singleton-backed shared store so isolated JavaScript heaps can synchronously read, write, subscribe, and optionally persist shared state. [src-2026-06-03-004]
- The README recommends the tool only when one or two expensive features repeatedly monopolize the main runtime; simple apps should first try ordinary memoization, virtualization, or moving work out of render. [src-2026-06-03-004]
