# DigUp repository README and privacy claims

## Summary
The DigUp README describes a native app for searching selected Mac folders with EmbeddingGemma 2. It claims on-device processing, limits network use to model download and update checks, and specifies Apple Silicon with macOS 14 or later. [src-2026-10-11-006]

## Key Claims
- The README says DigUp searches selected folders for images, screenshots, PDFs, documents, audio, and video. Code search is optional and off until the user enables it. [src-2026-10-11-006]
- The README says indexed content stays on the Mac. It claims the app connects to download the model once and check for updates daily, sends no file information in the update check, and has no account or telemetry. It says users can disable update checks. [src-2026-10-11-006]
- The README says the app does not upload, move, or change files. It lists folders and file types that it skips, including credentials, hidden folders such as `~/.ssh`, app bundles, caches, and iCloud-only files. These are project privacy claims, not an independent audit. [src-2026-10-11-006]
- The README identifies EmbeddingGemma 2 as a 740M-parameter model and says the download is 865 MB, including a 310 MB text component and 555 MB image/audio encoders. This differs from the post's ~250 MB text-encoder figure; the sources do not explain the difference. [src-2026-10-11-005] [src-2026-10-11-006]
- The README says DigUp requires Apple Silicon and macOS 14 or later. It describes a DMG or Homebrew install. [src-2026-10-11-006]
- The README lists DigUp as MIT-licensed and identifies EmbeddingGemma 2 as Apache 2.0, llama.cpp as MIT, and Sparkle as MIT. [src-2026-10-11-006]
