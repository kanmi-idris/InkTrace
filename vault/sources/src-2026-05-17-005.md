# TypeScript Binary Format Comparison Note

## Summary
This source captures a user-supplied architecture note comparing Protobuf, CBOR, and Avro from a TypeScript-backend perspective. Its main contribution is not any one format in isolation, but a layered decision model: Protobuf is positioned as the strongest default for typed high-performance service boundaries, CBOR as a flexible schema-light binary JSON alternative, and Avro as the better fit for streaming and schema-evolving event systems rather than ordinary API transport. [src-2026-05-17-005]

## Key Claims
- The note argues that binary formats matter when JSON becomes too verbose, slow, bandwidth-heavy, or weakly typed for a system’s scale and communication pattern. [src-2026-05-17-005]
- It presents Protobuf as the best first format to learn for TypeScript teams building RPC, gRPC, mobile, websocket, or service-oriented systems that need strong schemas and efficient binary exchange. [src-2026-05-17-005]
- It presents CBOR as a schema-optional compact binary JSON alternative that is especially attractive when flexibility and native binary-value support matter more than strict compiled schemas. [src-2026-05-17-005]
- It presents Avro as the better fit for Kafka, analytics, event sourcing, and long-lived schema-evolving event streams than for ordinary public APIs. [src-2026-05-17-005]
- A major architectural recommendation is to use different formats at different layers rather than forcing one universal serialization strategy across public APIs, internal RPC, realtime transport, and streaming infrastructure. [src-2026-05-17-005]
- The note also highlights tradeoffs explicitly: Protobuf brings stronger typing and performance but worse debuggability, CBOR is easier and more flexible but less type-safe, and Avro is powerful for streaming systems but often overkill at the start of a product. [src-2026-05-17-005]
