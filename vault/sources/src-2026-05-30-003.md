# Mouse Unlock click-pattern note

## Summary
This source captures a Linux desktop automation idea: a small Python daemon reads raw mouse events with `evdev`, detects a registered click pattern while the session is locked, and runs `loginctl unlock-sessions` from a boot-time `systemd` service. It is useful as an input-event and session-control experiment, not as a serious authentication design. [src-2026-05-30-003]

## Key Claims
- The workflow uses raw `/dev/input/` mouse events rather than ordinary app-level pointer events, which is why the note says it can work at the Wayland lock screen. [src-2026-05-30-003]
- The session state and unlock action are handled through `loginctl`, with the click-pattern daemon acting as a convenience trigger. [src-2026-05-30-003]
- Packaging the daemon as a `systemd` service makes the workflow available after boot without manually starting a script. [src-2026-05-30-003]
- The source explicitly states that the method is not secure, so it should be categorized as local automation and hardware-constrained convenience rather than passwordless authentication best practice. [src-2026-05-30-003]

## Notes
- This is weak but useful direct evidence. Any future implementation should document threat model limits clearly, because a click pattern is observable and replayable in ways that biometric or cryptographic authentication is not.
